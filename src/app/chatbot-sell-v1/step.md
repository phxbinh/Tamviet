# BẢNG TỔNG HỢP KIẾN TRÚC CÁC TẦNG DỮ LIỆU TRONG HỆ THỐNG RAG

| Thứ tự | Thành phần (Component) | Kiểu dữ liệu & Cấu trúc (Data Type & Structure) | Cách lưu trữ (Storage Method) | Thành phần tiêu thụ (Consumed by) | Mục đích & Thời điểm sử dụng (Purpose & Trigger) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **1** | **Knowledge** | **Input:** File gốc nhị phân/văn bản (`.pdf`, `.docx`, `.xlsx`).<br>**Output:** Chuỗi Plain Text thuần túy sau khi làm sạch rác. | Lưu tạm trong RAM hoặc lưu thành các file Text/Markdown sạch trên Ổ đĩa (Disk). | `Chunking` (Bước 2) | **Mục đích:** Khởi tạo kho tri thức nguồn.<br>**Khi nào:** Giai đoạn chuẩn bị dữ liệu ban đầu (Offline). |
| **2** | **Chunking** | **Input:** Chuỗi Plain Text sạch.<br>**Output:** Mảng các đoạn văn bản ngắn (Markdown String), bảo toàn nguyên khối các thẻ `\|` (bảng) và `$$` (LaTeX). | Lưu trong bộ nhớ đệm (Memory Buffer) để chuyển tiếp sang bước tạo vector. | `Embeddings` (Bước 3) & `Vector Store` (Bước 4) | **Mục đích:** Băm nhỏ dữ liệu vừa tầm đọc của AI, tránh làm loãng nghĩa.<br>**Khi nào:** Ngay sau khi có Text sạch. |
| **3** | **Embeddings** | **Input:** Đoạn văn bản nhỏ (Markdown String).<br>**Output:** Mảng số thực đa chiều (Dense Vector, ví dụ: `[0.12, -0.43, ..., 0.89]` - 1536 chiều). | Lưu tạm trong bộ nhớ RAM dưới dạng mảng (Array/Tensor). | `Vector Store` (Bước 4) | **Mục đích:** Số hóa ngữ nghĩa và cấu trúc hình học thành toán học.<br>**Khi nào:** Ngay sau khi dữ liệu được chia nhỏ thành Chunk. |
| **4** | **Vector Store** | **Input:** Cặp bài trùng `[Vector Embedding + Metadata Text gốc]`.<br>**Output:** Cơ sở dữ liệu đã đánh chỉ mục (Indexed Database). | Lưu trữ vĩnh viễn trong **Vector Database chuyên dụng** (Index dạng HNSW/IVF). | `Retriever` (Bước 6) | **Mục đích:** Lưu trữ tri thức dài hạn phục vụ tra cứu siêu tốc bằng toán học.<br>**Khi nào:** Kết thúc giai đoạn chuẩn bị dữ liệu Offline. |
| **5** | **Query Refinement** | **Input:** Chuỗi text câu hỏi thô từ User + Lịch sử hội thoại.<br>**Output:** Chuỗi text câu hỏi mới đã làm mịn (hoặc bảng JSON chứa thuộc tính). | Lưu trong Session Memory của người dùng (Redis / RAM cache). | `Retriever` (Bước 6) | **Mục đích:** Làm rõ nghĩa câu hỏi, loại bỏ đại từ mơ hồ, tối ưu hóa token.<br>**Khi nào:** Ngay khi User gửi câu hỏi lên hệ thống (Online). |
| **6** | **Retriever** | **Input:** Câu hỏi đã làm mịn (được convert sang Query Vector).<br>**Output:** Top 15 - 20 bản ghi thô (Mảng gồm các đoạn Text Markdown + Điểm số tương đồng). | Lưu tạm trong RAM của Backend. | `Re-ranking` (Bước 7) | **Mục đích:** Quét nhanh trên diện rộng để bốc ra sập tài liệu có triển vọng nhất.<br>**Khi nào:** Khi nhận được Query Vector từ User. |
| **7** | **Re-ranking** | **Input:** Mảng 15-20 bản ghi thô từ bước 6.<br>**Output:** Mảng 3-5 bản ghi tinh túy nhất, được sắp xếp lại theo thang điểm liên quan Cross-Encoder. | Lưu tạm trong RAM của Backend. | `Context Injection` (Bước 8) | **Mục đích:** Lọc tinh, sửa sai số của bộ tìm kiếm vector, đưa tài liệu chuẩn nhất lên đầu.<br>**Khi nào:** Sau khi Retriever lấy được tài liệu diện rộng. |
| **8** | **Context Injection** | **Input:** Mảng 3-5 bản ghi tinh túy dạng Markdown.<br>**Output:** Một khối văn bản lớn (String Block) được phân tách khoa học bằng các thẻ giả XML (ví dụ: `<DOCUMENT id="1">... </DOCUMENT>`). | Lưu trong biến chuỗi (String Variable) ở RAM. | `Prompt Design` (Bước 9) | **Mục đích:** Đóng gói tri thức thành một cấu trúc mạch lạc, có nhãn mác rõ ràng để LLM dễ đọc đọc số liệu.<br>**Khi nào:** Ngay trước khi chế tạo Prompt. |
| **9** | **Prompt Design** | **Input:** Khối ngữ cảnh XML + Chỉ thị hệ thống (System Prompt) + Câu hỏi hiện tại.<br>**Output:** Một chuỗi Prompt tối cao hoàn chỉnh (Final Prompt System Schema). | Lưu trong RAM để chuẩn bị bắn qua giao thức API Network. | `Generator` (Bước 10) | **Mục đích:** Tạo ra bộ khung chỉ thị "thiết quân luật" ép LLM làm việc đúng khuôn khổ pháp lý kỹ thuật.<br>**Khi nào:** Khi đã có đủ nguyên liệu (Context và Query). |
| **10** | **Generator** | **Input:** Chuỗi Prompt tối cao hoàn chỉnh.<br>**Output:** Chuỗi văn bản thô (Raw Text Response) chứa câu trả lời, bảng Markdown và công thức LaTeX do LLM sinh ra. | Lưu tạm trong RAM Backend. | `Grounding` (Bước 11) | **Mục đích:** Sử dụng trí tuệ của LLM để tổng hợp tài liệu và đẻ ra câu chữ trả lời.<br>**Khi nào:** Khi nhận được API Call chứa Prompt hoàn chỉnh từ Backend. |
| **11** | **Grounding** | **Input:** Chuỗi văn bản trả lời thô của AI + Khối ngữ cảnh XML gốc ở bước 8.<br>**Output:** Trạng thái Phê duyệt (`Pass` / `Fail`) kèm theo Câu trả lời an toàn tuyệt đối. | Đẩy dữ liệu sạch ra UI hiển thị cho User, đồng thời đẩy bản sao vào hệ thống Logs. | `Evaluation Loop` (Bước 12) & Giao diện người dùng (UI) | **Mục đích:** Kiểm toán chéo, triệt tiêu lỗi ảo tưởng số liệu hoặc sai lệch công thức LaTeX.<br>**Khi nào:** Trước khi hiển thị câu trả lời lên màn hình người dùng. |
| **12** | **Evaluation Loop** | **Input:** Toàn bộ Logs phiên chạy (Query, Context XML, AI Response, Grounding Score).<br>**Output:** File báo cáo/Bảng Dashboard chứa bộ 3 điểm số toán học (RAG Triad Metrics). | Lưu trữ lâu dài trong các hệ thống giám sát dữ liệu (APM Logs / SQL DB để phân tích Analytics). | Lập trình viên / Kỹ sư hệ thống (Mắt người đọc) | **Mục đích:** Đo lường sức khỏe hệ thống trên diện rộng để liên tục nâng cấp thuật toán Chunking/Embedding.<br>**Khi nào:** Chạy bất đồng bộ (Async) liên tục song song với quá trình vận hành hệ thống. |
